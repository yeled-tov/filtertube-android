# FilterTube — גרסת החנות

זו הגרסה של FilterTube שמיועדת ל‑Google Play ול‑App Store. היא מעתיקה את
הממשק, הפיצ'רים וההגדרות של אפליקציית האנדרואיד שבשורש המאגר, אבל **כל
התוכן עובר דרך המקורות הרשמיים של YouTube בלבד**: ה‑Data API v3, פיד ה‑RSS
הציבורי של הערוצים, ונגן ה‑IFrame הרשמי.

## מה שונה, ולמה

**אין הורדות, אין ניגון ברקע, אין חלון צף (PiP).** נגן ההטמעה הרשמי של
YouTube אינו מתיר אותם, וזה מה שמאפשר לאפליקציה הזו להתפרסם בחנויות.

**Premium מוכר משהו אחר, ודרך החנות.** בגרסה הראשית המנוי מכר הורדות
וניגון ברקע — שניהם לא קיימים כאן. במקומם המנוי פותח **סנכרון וגיבוי
בענן**, **אלבומים ללא הגבלה** (בחינם: עד 3) ו**בקשות ערוץ בעדיפות**.
החיוב עובר דרך Google Play Billing ו‑StoreKit בלבד: מסך תשלום שמפנה
למייל או ל‑Stripe, כמו בגרסה הראשית, הוא עילת דחייה מפורשת בשתי החנויות.

> מה בדיוק נמכר הוא החלטה עסקית ולא טכנית. הרשימה למעלה היא מה שמימשתי,
> והיא מרוכזת בשני מקומות בלבד: `Cloud.syncAllowed` ו‑
> `LibraryStore.canCreatePlaylist`. שינוי שלה הוא שינוי של שתי שורות.

**אין שיתוף קובץ APK ואין "הורד והתקן" מתוך האפליקציה.** Google Play אוסר
על אפליקציה להפיץ או לעדכן את עצמה מחוץ לחנות. "שתף" מפנה עכשיו לדף
האפליקציה בחנות, עם אותו קוד QR.

**אין חיבור לחשבון YouTube (לייקים, מנויים והיסטוריה מהחשבון).** הגרסה
הראשית מושכת אותם דרך InnerTube, שאינו ממשק רשמי. המקבילה הרשמית היא OAuth
מול YouTube Data API, והיא דורשת רישום מזהי לקוח ל‑Android ול‑iOS בקונסולת
Google Cloud — ראה "מה נשאר לעשות" למטה.

**אין "מומלצים מיוטיוב".** גם הוא הגיע מ‑InnerTube ואין לו מקבילה רשמית.
במקומו הרדיו האישי והמיקסים, שנבנים מהטעם של המשתמש ומהערוצים המאושרים.

**אין "במכשיר שלי"** (ניגון קבצים מהטלפון). הוא דורש הרשאות גישה לאחסון
שאין לאפליקציה שום שימוש אחר בהן, וב‑iOS הוא ממילא מוגבל לספריית
האפליקציה. הוספת הרשאה כזו רק כדי לכסות פיצ'ר צדדי היא בדיוק מה ששתי
החנויות מבקשות להימנע ממנו.

**הגדרות שמע מתקדמות חסרות ב‑FilterMusic** (דילוג על שקט, הגברת עוצמה,
גובה צליל, עמעום מוצלב). כולן פעולות על זרם האודיו, ונגן ההטמעה לא נותן
אליו גישה. מתג שנראה כאילו הוא עושה משהו ולא עושה כלום גרוע מהיעדרו.

**החשבון אינו חובה.** באפליקציה הראשית הכניסה חסומה עד הרשמה. כאן הסינון,
הספרייה וההעדפות מקומיים לגמרי, והחשבון נדרש רק לסנכרון, לבקשות ערוץ
ולדיווחים. חסימת האפליקציה מאחורי הרשמה היא עילה מוכרת לדחייה בבדיקת
App Store (Guideline 5.1.1(v)) ואין לה כאן תמורה.

## למה הפיד מגיע מ‑RSS ולא מ‑playlistItems

הרשימה הלבנה מונה מאות ערוצים. רענון אחד דרך ה‑Data API עולה יחידת מכסה
לכל ערוץ — כלומר מכסת היום כולה (10,000 יחידות) נשרפת תוך כמה עשרות
רענונים, על פני **כל** המשתמשים יחד. פיד ה‑RSS של יוטיוב
(`youtube.com/feeds/videos.xml`) הוא מקור רשמי ופומבי, ללא מכסה, וזה בדיוק
מה שהאפליקציה הראשית משתמשת בו. ה‑Data API נשמר לחיפוש, לשידורים חיים
ולהעשרת מטא‑דאטה — שם הוא באמת נחוץ, ושם הוא זול (בקשה אחת ל‑50 סרטונים).

## מה נשאר לעשות לפני פרסום

1. **מוצרי המנוי בחנויות** — יש ליצור ב‑Play Console וב‑App Store Connect
   שני מוצרי מנוי במזהים `filtertube_premium_monthly` ו‑
   `filtertube_premium_yearly` (או לשנות את המזהים ב‑`AppConfig`). בלעדיהם
   מסך Premium יציג "לא נמצאו מסלולי מנוי".
2. **אימות קבלות בצד השרת (מומלץ)** — כרגע הזכאות נקבעת מהתשובה של החנות
   במכשיר. לפני שהמנוי שווה כסף אמיתי כדאי להוסיף ל‑Cloud Functions אימות
   מול Google Play Developer API ומול App Store Server API, ולשמור את
   הזכאות ב‑Firestore — בדיוק כמו שהגרסה הראשית עושה מול הספק שלה.
3. **מפתח Web של Firebase** — `AppConfig.firebaseWebApiKey` ב‑`lib/config.dart`.
   נמצא ב‑Firebase Console → Project settings → General → Web API Key. בלעדיו
   מסך החשבון מסביר שהחשבון לא הוגדר, ושאר האפליקציה עובדת כרגיל.
4. **הגבלת מפתח ה‑YouTube API** ב‑Google Cloud Console — לחבילה ולחתימה של
   אפליקציית Android, ולמזהה החבילה של iOS. המפתח גלוי בתוך החבילה, ובלי
   הגבלה כל אחד יכול לשרוף את המכסה.
5. **מדיניות פרטיות ותנאי שימוש** בכתובות שב‑`AppConfig` — שתי החנויות
   דורשות קישור פעיל, ומסך "פרטיות ותנאים" כבר מפנה אליהן.
6. **קישור החנות** ב‑`AppConfig.storeListingUrl` / `appleListingUrl` — מה
   ש"שתף" וה‑QR מפנים אליו.
7. **אייקון ומסך פתיחה** — כרגע אייקון ברירת המחדל של Flutter.
8. **iOS**: לפתוח את `ios/Runner.xcworkspace`, לקבוע Bundle ID וצוות פיתוח,
   ולהריץ `flutter build ipa`. אין הרשאות מיוחדות מעבר להתראות.
9. **חיבור חשבון YouTube (אופציונלי)** — אם רוצים למשוך לייקים ומנויים
   מהחשבון: ליצור מזהי לקוח OAuth ל‑Android ול‑iOS, למלא אותם ב‑`AppConfig`,
   ולהוסיף את `google_sign_in` עם היקף `youtube.readonly`.
